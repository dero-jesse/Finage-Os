FINAGE OS USER MANUAL
====================

Purpose
-------
This guide explains the main screens and the everyday tasks available in Finage OS. Your organization, assigned role, permissions, and enabled services determine which screens and actions you can use. Screen labels may vary slightly by version.

CURRENT ONLINE MIGRATION STATUS
-------------------------------
This build is not yet a fully online operational banking system and is not ready for general live financial use. Sign-in, organization discovery, and authorized reads of tenant roles, users, branches, members, the General Ledger, transactions, and audit trail use Supabase. Browser storage is no longer used to save operational data. An online gate enables only actions for which the server confirms a permission-specific atomic RPC: member creation; teller/member cash deposits and withdrawals; loan repayments; and manual two-leg GL journals. Other teller, credit, workflow, treasury, setup and administration actions remain blocked. Rejected or offline writes are not treated as success.

For an enabled action, the form waits for the Supabase response and displays a reference only after server acceptance. Posting updates GL balances, the member balance or loan payment history, the authenticated operator's branch/till cash, the transaction record and audit trail in one database transaction. Repayments require a selected member-owned loan. Manual journals require the server-confirmed GL-journal permission and balanced valid legs. If the server accepts a post but the follow-up read fails, the UI reports acceptance and the refresh problem separately; do not repeat it with a new reference.

One-time legacy import
----------------------
An organization administrator can use “Review browser records for one-time import” when the tenant lists visible to the current account are empty. The review step reports supported records before requiring a separate confirmation. Supabase then checks tenant emptiness authoritatively inside the import transaction and rejects the request if any branch, GL account, member, transaction, audit event, or previous import batch exists; remote data is never overwritten. The import supports branches (including teller/vault state), GL accounts, members (including embedded active-loan data), transactions, legacy GL journal entries preserved in transaction details, audit trail, and migration counts. It does not migrate roles/users, workflow queues, product configuration, treasury portfolios, or other module-only state. Those records require a separate migration.

Deployment prerequisite: apply `online_data_migration.sql` to an existing Supabase installation before using the import control. It revokes direct browser DML on existing tenant schemas and removes authenticated direct access to the setup write RPC; fresh installations created from the updated `platform_schema.sql` start with tenant tables read-only. Then apply `online_financial_writes.sql` to enable the bounded RPCs described above. These migrations do not delete or rewrite existing rows. Tenant schemas must be exposed through the existing platform provisioning/security configuration. Verify the target organization and a current backup before approving an import. The selected browser's legacy cache is removed only after Supabase confirms successful import. Sign-in tokens and the last selected organization preference may still use browser storage; operational records may not.

1. SIGN IN AND SELECT AN ORGANIZATION
-------------------------------------
1. Open Finage OS in the web browser provided by your administrator.
2. For a new account, select Use an email code, enter your work email, and verify the one-time code sent to that inbox. Set a personal password when prompted. For an existing account, sign in with your password.
3. Do not share your password, email code, or account.
4. If you are asked to select an organization, choose the organization you are authorized to work in.
5. Check the organization name in the application header before posting, importing, exporting, or changing setup.
6. If no organization is available, or the wrong organization is shown, contact your platform administrator. Do not enter records under another organization's workspace.
7. In this migration build, the online-readiness gate is expected. Use only the specific actions shown there; the full operational workspaces remain unavailable. Do not attempt to bypass the gate.

2. NAVIGATION BASICS
--------------------
- The role buttons in the header switch between the Teller, FOSA, Treasury, Credit, and Board workspaces when your permissions allow it.
- Select Actions to open Input Hub, Users, Organization Setup, Reports, and other available commands.
- Select the menu icon at the left of the header to open the portal navigation drawer.
- Use the close button on a modal to return to your workspace. If a modal is still open, close or cancel it before starting another task.
- A posting reference appears only after Supabase confirms a supported write. If a write is rejected or the result is uncertain, do not claim success or submit a new reference without first resolving the original request.

Keyboard shortcuts:
- Alt+N opens the Input Hub.
- Alt+U opens User Access when your account has user-management permission.

The remaining operational sections are retained as feature reference only. Their actions are disabled by the online-readiness gate in this migration build unless explicitly listed as a supported online action above.

3. TELLER AND MEMBER OPERATIONS
-------------------------------

Post a member transaction
1. Open Actions > Input Hub > Transactions, or press Alt+N and select the Transactions tab.
2. Select the member and transaction type.
3. Enter the amount and choose the delivery channel that matches how funds were received or paid.
4. Review the GL Impact preview. It shows the debit and credit accounts that will be used.
5. Enter a useful reference, such as a receipt, deposit slip, or payment reference.
6. Select Post Real-Time Transaction.
7. Confirm the success message and check the member balance or General Ledger report as appropriate.

The transaction screen provides configured types such as member deposit, withdrawal, loan repayment, share capital purchase, fixed-term placement, dividend distribution, loan-loss provision, and service fee. Only use a type when it matches the underlying transaction. A transaction is rejected if required accounts or permissions are missing.

In the Teller portal, select the currency and transaction, then enter the number of notes/coins for each denomination. The target amount is calculated from those counts and updates automatically; it is not manually editable. Check the physical total and confirmation amount before posting. Cash counter transactions may require an assigned teller till, sufficient drawer cash for a withdrawal, and compliance with approval limits. If a post is rejected, do not retry with a different amount or channel just to bypass the control; ask the supervisor to review the rejection.

Register a member
1. Open Actions > Input Hub > New Member.
2. Enter the member's identity and contact details, branch, occupation, and employer as requested.
3. Select the primary account type and funding channel.
4. If an opening deposit is being taken now, confirm the amount. The opening deposit posts through the configured GL mapping.
5. Select Register & Onboard Member and verify that the member appears in the system.

Only enter information collected and verified in line with your organization's KYC procedures. If the initial deposit is zero, the member is registered without an opening transaction.

4. CREDIT OFFICER PORTAL
------------------------

Submit a loan application
1. Switch to the Credit workspace and open Applications, or choose Actions > Input Hub > Loans.
2. Choose the applicant, loan product, requested principal, term, purpose, urgency, branch, and guarantor where required.
3. Review the displayed liquidity headroom and pacing information.
4. Select Submit to Credit Workflow Queue. The application receives a reference and remains pending until a different authorized checker reviews it.
5. Track its review, decision, pacing, and disbursement status in Credit > Applications. Approval does not itself disburse funds.

Review a credit task
1. Switch to the Credit workspace.
2. Review the task, amount, maker, status, and liquidity check in the workflow inbox.
3. Use Review & approve or Return / reject only if your role permits it and you have completed the required checks. Rejection requires a reason.
4. Follow your organization's maker-checker policy. Do not approve a request that you initiated when segregation of duties applies.
5. An approved application enters the pacing queue. An authorized checker must separately confirm disbursement.

Manage products, repayments, and penalties
- Credit > Client loans shows disbursed loan balances, instalments, due dates, repayment activity, and assessed penalties.
- Credit > Products & rates lets an authorized credit checker create loan products and configure annual interest, flat or reducing-balance repayments, penalty grace days, a fixed late fee, and a simple daily rate.
- Existing sample product rates are unconfirmed defaults. An authorized credit checker must save/confirm each product's approved rate before it can be selected for a new application; zero interest may be confirmed where that is the approved policy.
- A new loan snapshots its product terms. Later product changes apply only to new applications.
- Credit > Collections & penalties lists overdue scheduled instalments. Suggested penalties use the saved product policy and remain subject to checker review and adjustment. The fixed fee is charged once per overdue instalment; the daily rate is simple, not compounded.
- A recorded penalty is tracked on the loan account only. This release does not collect the penalty or post it to the General Ledger; follow the approved accounting and collections procedures.
- Loan repayments should be posted through the existing Transactions workflow and linked to the correct member and loan. Repayments are applied to scheduled instalments in due-date order for arrears tracking.

Post a loan-loss provision
Use the Credit workspace's Post NPA Provision action for an approved provision. The configured entry is Dr 5030 Loan Loss Provision Expense and Cr 1250 Allowance for Loan Impairment. Review the amount and authorization before posting.

5. EXPENSES AND GENERAL LEDGER JOURNALS
--------------------------------------

Add a planned recurring operating cost
1. Open Actions > Input Hub > Opex.
2. Enter the expense description/category, monthly amount, and due day.
3. Select Save OpEx Schedule Line.

This creates an operating-cost schedule for cash forecasting. It does not record an actual payment or post an expense to the General Ledger.

Post an actual or miscellaneous expense
1. Confirm that you have authority to post a GL journal and are in the correct organization.
2. Open Actions > Input Hub > GL Journal.
3. Select the appropriate expense account as the debit account. Examples in the sample chart include:
   - 5010: staff salaries and employee benefits.
   - 5020: branch operating and technology costs.
   - 5040: interest expense on member deposits.
   - 5030: loan-loss provision expense; normally use the Credit workspace provision action instead.
4. Select the account that actually funded the expense as the credit account. Examples include 1020 for a bank payment, 1010 for physical branch cash, or 1040 for digital-channel float.
5. Enter the same amount for both sides and describe the purpose, date, supplier, and invoice/payment reference.
6. Select Post Balanced Journal.
7. Verify the entry in the General Ledger report and check the Treasury trial-balance status.

Example: a bank-paid UGX 250,000 branch bill is Dr 5020 UGX 250,000 and Cr 1020 UGX 250,000. Select accounts and codes that match your organization's approved chart; sample codes may not match your accounting policy.

The journal requires equal debit and credit amounts, two different valid accounts, and a posting that leaves the ledger balanced. It does not replace invoice approval, payment authorization, tax processing, or supporting-document retention. Follow your organization's procedures for those controls.

6. TREASURY AND LEDGER CHECKS
-----------------------------
- Open the Treasury workspace to review liquidity, the accounting check, and the General Ledger snapshot.
- Review the full General Ledger trial balance and all accounts directly in the Treasury workspace, including debit and credit totals and variance. Use the chart filters to display assets, liabilities, equity, income, or expenses; the All filter displays the full chart. CSV export is optional.
- Select Verify Ledger to run a trial-balance/accounting-equation check. Review any flagged variance before further posting and notify the finance supervisor.
- Select Trial Balance or Balance Sheet to export a copy of the relevant report if needed.
- Use the Input Hub's DFI tab to register a facility or record a drawdown. A drawdown posts using the configured bank and DFI liability accounts; verify the facility availability and destination bank before submission.

7. ORGANIZATION SETUP AND MIGRATION
-----------------------------------
Organization Setup is for users with organization-management permission.
1. Open Actions > Organization Setup. An incomplete-setup notice may also provide a Continue Setup button.
2. Review the organization profile and branch list.
3. Choose a direct-entry option to add a branch, member, GL account, or opening balance; or choose the applicable CSV type and select a CSV/workbook file.
4. For a chart account, enter a unique GL code, account name, category, normal balance (Debit or Credit), and account type.
5. For an opening balance, enter the same GL code used in the chart and the signed amount according to the import instructions/accounting convention provided by your finance administrator.
6. Review displayed row counts, import errors, unknown GL codes, and opening-balance control totals.
7. Select Save Setup only after resolving errors and confirming that opening debit and credit totals balance.

Migration files can contain more detailed history than the application currently maps to live modules. Some supported records are retained in the migration archive for reconciliation rather than appearing as live operational records. Do not assume that an imported archive row has created a live account or transaction; check the relevant module and reports after saving.

8. REPORTS AND EXPORTS
----------------------
1. Open Actions > Reports.
2. Choose a category: Clients, Savings, Fixed Deposits, Shares, Loans, or Ledger.
3. Set the From and To dates where applicable.
4. Choose CSV or XLSX, then select Generate Report.
5. Review the preview and verify the organization and report category before using the exported file.

Exports may contain confidential financial or member information. Store and share them only through approved organization channels. Reports reflect records available to the selected workspace; they are not a substitute for external regulatory approval or reconciliation.

9. USER ACCESS AND ADMINISTRATION
---------------------------------
Users with user-management permission can open Actions > Users or press Alt+U.
- Operators lists users, assigned roles, branch assignments, approval limit, and status.
- Permissions displays the task-permission matrix.
- Add User is used to enter a new operator's name, official email, role(s), branch, and approval ceilings. In a connected environment, the new operator receives an email code and must set a personal password before accessing the organization.
- Edit Roles is used to change an existing operator's role assignment.

Assign only the access needed for a person's duties. Confirm roles, branch, status, and transaction limits with the organization administrator. User management should not be used to bypass maker-checker or approval controls.

10. BOARD, AUDIT, AND REPORTING
-------------------------------
The Board workspace provides portfolio, liquidity, cash forecast, and audit-related views and exports. Forecasts are planning information, not posted transactions or guaranteed outcomes. Use export buttons only for authorized oversight or reporting work, and validate the period and organization before sharing results.

11. COMMON PROBLEMS
-------------------
- Organization not selected: return to organization selection or ask the administrator to grant access to the correct organization.
- Action or tab is missing: your role may not include permission for it. Ask the administrator to review the permissions matrix.
- Journal rejected: confirm both GL codes exist, the accounts have Debit/Credit normal balances, the amount is positive, and the proposed entry preserves ledger balance.
- Opening balance rejected: confirm every code exists in the chart and that total opening debits equal total opening credits.
- Import errors: correct the indicated source file row/column and re-import. Keep the original migration file for reconciliation.
- A success message appears but data seems missing: confirm the organization in the header, check the relevant report/module, and verify sync status. Do not repeat a financial transaction until its first result is checked.
- Unexpected result or suspected duplicate: stop posting and contact the finance administrator with the organization, transaction reference, date, amount, and screenshot. Do not include passwords or authentication tokens.

12. SAFE OPERATING PRACTICES
----------------------------
- Confirm the organization and environment before every financial post or import.
- Check member, account, branch, amount, channel, and reference before submitting.
- Keep receipts, invoices, approvals, and source migration files according to your organization's record-retention policy.
- Never share accounts or passwords. Sign out when leaving a shared workstation.
- Do not use demo data or sample accounts as a guide to a real organization's approved chart without confirming mappings with Finance.
- Reconcile reports and external bank/member records according to your organization's close procedures.
- Contact your Finage OS administrator for access problems, environment questions, or suspected data issues.
